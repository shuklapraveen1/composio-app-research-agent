Key insight

Two numbers are reported for every sample because one of them alone is misleading. Field-level accuracy asks how many individual values are right. Row-level accuracy asks how many applications are right in every field, and it is always much lower. A pipeline that quotes only the first is hiding the second.

The rules that changed

Each failure was traced to the rule that produced it, and the rule was changed once for every application rather than patched per app. The classifier version is recorded on every record, so which rules produced which value is never in doubt.

ChangeFailure modeWhat v2 does insteadSample A misses
api breadth coverage anchorAPI breadth was a count of documented resource groups, so a large reference covering one corner of a product scored very_broad.v2 caps the count-derived breadth by the documented share of the product the API actually covers.1
blocker completenessBlockers were only named when an app was blocked outright, so 'buildable with friction' records were silent about the friction, and unblocked apps read as though nothing had been established.v2 names friction blockers explicitly and records 'none' when the decision tree found nothing in the way.14
credential access plan gatingCredential access was read off the signup tier alone, so a product with a free account but a paid-only API was recorded as self_serve_free.v2 resolves credential access from the plan that actually unlocks the API, together with partner, approval and self-hosting gates, and derives the matching access restrictions rather than copying only those the source spelled out.6
derived restriction provenanceAccess restrictions were cited to the credential page without saying so, so the citation audit read them as claims the page never made.v2 records restrictions as derived from the documented access conditions and says so in the rationale, so the audit judges the citation as support for a conclusion rather than as a quotation.0
event mechanism distinctionAnything event-like was recorded as native_webhooks, which erased the difference between a callback, a gateway stream and polling.v2 keeps the observed event mechanism as the source states it.1
Verification design

Four channels, and what each one can catch

A

Research

100 applications

Gathers sources and classifies every field.

B

Independent re-derivation

30 sampled applications

Reads the same sources with different rules, without seeing Channel A's answer.

C

Citation audit

30 sampled applications

Checks that each cited page supports the field it is cited for.

D

Human review

32 adjudicated fields

Rules on disputed and triggered fields, and stays silent everywhere else.

Channel B is blind to Channel A. It does not see the recorded answer and does not share the classifier's rules, so agreement between them is evidence rather than an echo. Channel D is silent unless a reviewer actually ruled on a field: a human rubber-stamping the pipeline's own output would make the accuracy number circular.

Method

How the pipeline works

Deciding which integrations to build is a research problem before it is an engineering one. The facts that matter - is there an API, how broad is it, can a developer actually get credentials, what stands in the way - are scattered across vendor documentation, pricing pages and repositories, and they are exactly the kind of facts a language model will answer fluently whether or not it knows. So the pipeline is built around one rule: a value is worth nothing without the evidence behind it.

The stages are fixed in order. Select a stage to see what it does, what it covers, and why it is there.

Registry

Scope
100 applications

Ids have to be stable and order-independent, or every later stage would reshuffle when the input list is re-sorted.

Research

What it does
Channel A reads the sources for every application and records what they say.
Scope
100 applications
Why it exists
This is the only stage that touches all one hundred, which is what keeps the cost of the expensive checks bounded.

Evidence extraction

465 evidence items
What it does
Each claim becomes an evidence item with a URL, a source type and the fields it supports.
Scope
465 evidence items
Why it exists
A value that cannot name the page it came from is an opinion, and the citation audit later needs something to audit.

Classification

13 fields per application
What it does
Deterministic rules map the observations onto the fixed taxonomy.
Scope
13 fields per application
Why it exists
Rules can be versioned, diffed and re-run; a model's judgement cannot, so the improvement phase would have nothing to change.

Validation

100 records checked
What it does
Pure checks: cited evidence exists, derived values follow from their inputs.
Scope
100 records checked
Why it exists
Catches contradictions mechanically before a human spends attention on them.

Trigger review

16 of 100 queued
What it does
Risk rules queue records with unresolved identity, contradictions or missing critical evidence.
Scope
16 of 100 queued
Why it exists
Review capacity is finite, so it goes where the risk is rather than spreading evenly over a hundred applications.

Sampling

2 x 15 applications
What it does
Two disjoint stratified samples, seeded from the master seed and frozen at selection.
Scope
2 x 15 applications
Why it exists
Freezing Sample A before the improvement phase is what stops a better classifier from retroactively improving its own first-pass score.

Verification

30 applications
What it does
Channels B, C and D re-derive, audit citations and adjudicate disputes.
Scope
30 applications
Why it exists
Verification only means something if the channels are able to disagree, so they do not share rules or see each other's answers.

Reconciliation

330 decisions
What it does
Fixed precedence D > C > B > A; single-valued disputes downgrade to unclear, multi-valued merge.
Scope
330 decisions
Why it exists
Settling a disagreement by majority would invent a winner; recording it as unclear keeps the disagreement visible.

Two judgements that are not left to a model

Confidence is a function of recorded properties of the evidence: whether the product was identified, whether the vendor's own documentation was cited, whether every critical field carries evidence, whether anything contradicts anything else, and how many distinct sources were found. A record reaches high only with all of those and at least 3 sources. A single missing critical field, an unresolved identity or a lone source drops it to low regardless of how confident the prose sounded.

API breadth anchors

so the word means the same thing for every app
BreadthWhat it means
narrowSmall set of resources or capabilities.
moderateMeaningful API coverage but limited to a subset of the product.
broadMany important resources with meaningful action/CRUD coverage across major product surfaces.
very broadExtensive coverage across most major product capabilities.

Buildability is a decision tree, not an opinion

Three independent legs are answered first, and the verdict is the worst of them, with a definite failure outranking a gap. That is why a product with an excellent API can still be blocked: the API was never the binding constraint. Each leg, and the evidence confidence behind it, is recorded on every application and shown in its detail panel.

Technical feasibility

Is there an API, and does it cover a meaningful part of the product?

api_exists, api_breadth, api_capabilities

Credential accessibility

Can a developer obtain working credentials, and on what terms?

credential_access, authentication

Commercial accessibility

Does reaching the API require a paid plan, a contract or a partner programme?

access_restrictions, blocker

Three ways of not knowing

The taxonomy separates what a single "unknown" would collapse. not_found means the sources did not say. unavailable means they did say, and the answer is that the thing does not exist. unclear means the sources disagree or the question does not resolve to one value. The difference matters: absence of evidence and evidence of absence lead to different decisions.

Research boundaries

What this does not establish

These are the limits of the claim, kept next to the claim rather than at the bottom of a page nobody reaches.

Evidence is cited, not fetched in this run

The committed run replays a reviewed source corpus so that anybody can reproduce it byte for byte without credentials or network access. Every evidence item records retrieval: cited for exactly this reason. A live run would record fetched and carry page excerpts.

5.3% of verified field values are unresolved

That is reported rather than filled in. A confident wrong answer is more expensive than an admitted gap.

One reviewer

Channel D is a single human. Inter-rater agreement is not measured, so the reconciled values inherit that reviewer's judgement on the 32 fields they ruled on.

The taxonomy has gaps

Self-hosting is friction that no blocker value names, so it is carried as other and flagged. API breadth is a judgement anchored to documented resource groups; reasonable readers disagree, and Sample B's remaining misses are mostly exactly that disagreement.

Accuracy is measured on 15 applications per sample

Fifteen apps is enough to locate systematic rule failures and far too few to put a tight confidence interval around the headline number.

Findings are a snapshot

Pricing, plans and MCP servers move; the dataset records what the sources said as of 2026-09-16.
